Search for code using jbcontext semantic search in the specified repository or repositories.
- Use this tool when you need to find code whose location you don't already know - e.g., when the task asks 'where is X', 'how does Y work', or describes behavior or intent without naming exact symbols.
- When not to use: if you already know the relevant file, class, or symbol (use direct navigation or keyword search instead), or for non-code-discovery tasks such as git operations, builds, tests, or reviewing an existing diff.

This tool performs AI-powered semantic code search that understands code meaning and context, not just keyword matching. It finds relevant code even when exact terms differ. For best results, use detailed, descriptive queries that explain what you are looking for in natural language (e.g., "function that validates user email addresses and returns boolean" rather than just "email"). Returns a ranked list of file paths and code snippets with line numbers.

Results come from an index built at a specific commit, not from the working tree, so uncommitted or newly committed code may be missing. By default the search targets the snapshot indexed for the currently checked-out branch, falling back to the repository's default branch when that branch has never been indexed — which means results can describe a different branch than the one being worked on. The optional revision and branch parameters override that choice; leave both unset unless you specifically need a commit or branch other than the current checkout.
